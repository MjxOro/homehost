# @homehost/sites

A bounded JSON site spec, a pure deterministic static renderer, and an optional LLM generation pipeline for small business websites. **AI fills the spec; code renders the website.** Rendering makes no AI calls and accepts no user-supplied HTML, CSS, scripts, fonts or map URLs.

The version-1 spec has `business` (name, niche, optional contact details, service areas, weekly hours and HTTPS socials), `theme` (palette and system-font pairing IDs), and `pages` (unique slug, title, description and catalog sections). Exactly one page has the home slug `""`; there are at most 8 pages and 12 sections per page. Every free-text field and array is bounded. See [examples](./examples) for complete plumber, hair salon and café specs with invented Canadian business details.

The 13 section IDs are `hero.split-image`, `hero.centered`, `services.grid`, `about.text`, `testimonials.cards`, `gallery.grid`, `hours.table`, `contact.details`, `cta.banner`, `faq.list`, `pricing.table`, `team.cards` and `map.embed`. Images use HTTPS URLs or site-relative paths. Actions use HTTPS URLs, site-relative paths or fragment links. Section anchors follow the prefix (`#contact`, `#hours`, etc.), with numeric suffixes for repeats. Telephone/email links and Google Maps embeds come from business fields. Deploy referenced local image assets separately; rendering only emits text files.

```sh
bun packages/sites/src/cli.ts render packages/sites/examples/plumber.json /tmp/sites-out/plumber --base-url https://cedargroveplumbing.ca
bun test packages/sites
bun run --filter '@homehost/sites' typecheck
```

The CLI prints validation issues and exits 1 on errors; it prints warnings for derived image alt text or a map without an address. The default base URL is `https://localhost`; set the deployment URL for production SEO. It writes each page, shared `styles.css`, `sitemap.xml` and `robots.txt` and replaces files with the same names in the output directory. Base URLs may include a deployment path; site-relative actions and images refer to the host root.

The package exports `SiteSpec`, `Section`, `validateSpec`, `siteSpecJsonSchema`, `THEME_PRESETS`, `FONT_PAIRINGS`, `contrastRatio`, `renderSite`, `applySpecPatch`, `SpecPatchError`, `specFacts` and `findPlaceholders`. JSON Schema includes catalog variants and size limits; cross-page home/uniqueness checks also run through `validateSpec`. Patches support RFC 6902 add/remove/replace/move/copy/test, clone inputs, and validate the final spec. Invalid results throw `SpecPatchError` with `issues`. `specFacts` returns visible name, phone, hours and service-area strings; `findPlaceholders` returns `{ file, placeholder }` matches.

`generateSite(brief, { llm, models, concurrency?, onCall?, signal? })` validates `SiteBrief`, plans pages/theme/tagline once, then fills pages in parallel (default concurrency 4). The planner cannot choose `testimonials.cards`, `pricing.table` or `team.cards`, because the brief has no structured quotes, prices or staff; hand-authored specs may still use them. Structured outputs use section schemas, and code checks section order, renders the result, rejects placeholders and checks visible facts. One escalation is allowed per failed plan/page; a successful page is retained. Customer name, niche, phone, email, address, hours and service areas are copied in code; extra business fields in fill responses are ignored. `pagesWanted` means exactly home plus the named pages; `Home` is optional, duplicates are folded, and at most seven additional pages fit. Brief facts that cannot satisfy `SiteSpec` are rejected before billing.

Every model completion yields an `LlmCallRecord`, including transport and validation failures, with actual provider/model, usage, integer `costMicroUsd` and `hashLlmRequest(request)`. Calls are recorded in completion order; output pages retain plan order. Unrecoverable page failure stops scheduling new pages while already-running calls finish and are recorded. `onCall` receives every finished call and may be async; it is awaited, and a throw or rejection stops scheduling new work and fails generation without a paid cascade. `PROMPT_VERSION` hashes all prompt templates and schemas; the schema-derived catalog/system prefix stays fixed while the brief comes last for provider prompt caching. Results include `calls` and `escalated` on both success and failure.

`createOpenRouterClient({ apiKey, baseUrl?, timeoutMs?, maxRetries?, signal?, fetch? })` uses fetch, strict JSON Schema output and provider usage accounting. It retries 429/5xx/network errors twice by default with backoff; a `Retry-After` header (seconds or HTTP date) on 429/503 replaces the backoff, capped at 10 seconds, and a wait that would outlast the deadline fails with the HTTP status instead. Its default 60-second deadline covers the whole completion, including retries. Bind the same signal to the client and `generateSite` for transport cancellation plus scheduling cancellation. Arbitrary `LlmClient` implementations retain their own cancellation behaviour. HTTP error excerpts redact the key. A response without `usage.cost` fails with `missing_usage` (recorded as an error with the reported tokens and zero cost), so unknown cost is never metered as a free successful call; missing token fields are recorded as zero. Usage is read before the rest of the envelope, so billed metadata on empty-content and invalid-envelope responses is preserved.

```sh
# Set OPENROUTER_API_KEY in the environment (never in a committed file).
bun packages/sites/src/generate/smoke.ts packages/sites/examples/briefs/plumber.json /tmp/sites-gen/plumber
```

The smoke script defaults to `openai/gpt-oss-120b` for planning/escalation and `google/gemini-2.5-flash-lite` for fills. Override with `SITES_MODEL_PLAN`, `SITES_MODEL_FILL`, `SITES_MODEL_ESCALATE`; set `SITES_BASE_URL` for production SEO (default `https://localhost`). It writes the rendered site and `spec.json`, prints per-call tokens/status and total billed dollars, disables HTTP retries and caps the entire run at five actual HTTP attempts. Unit tests use scripted clients and injected fetch transports, never the live API.
